# IceClean 驱动管理实现方案

> 版本 v1.1（已根据"先显示已安装设备和驱动"诉求修订）
> 目标能力：本地驱动查询 → 驱动备份 → 驱动还原（恢复）。更新检查列为 P1 可选。
> 原则：优先使用 Windows 原生机制（pnputil / SetupDi / DriverStore），**禁止手写注册表遍历**，保证可回滚、可审计。
> 视图策略：**设备&驱动视图（SetupDi，主 Tab，默认在前）** + **驱动包视图（pnputil /enum-drivers，第二 Tab）**。

---

## 一、业界做法调研

### 1.1 系统原生机制

| 工具/API | 能力 | 优势 | 局限 |
|---|---|---|---|
| `pnputil /enum-drivers` | 列出 DriverStore 中全部第三方驱动包（oemXX.inf、提供商、类、版本、日期） | 官方、稳定、文本易解析 | 只有"包"视角，不含未装包的设备 |
| `pnputil /export-driver * <dir>` | **一键导出全部第三方驱动包**到指定目录 | 业界备份事实标准（Win10 1607+），产物即标准驱动包，可直接再导入 | 无细粒度进度输出 |
| `pnputil /add-driver <dir>\*.inf /subdirs /install` | 批量导入并安装驱动包 | 与导出互为逆操作；已存在同版自动跳过 | 安装动作影响系统，需前置还原点 |
| `DISM /Add-Driver` | 离线镜像加驱 | 救砖场景 | 在线场景不如 pnputil 直接 |
| SetupDi 系列（SetupDiGetClassDevs 等） | 设备级枚举：硬件名、厂商、版本、签名状态、问题码 | 信息最丰富，可做"按设备查看" | 代码量大；只读场景为主 |
| DriverStore FileRepository 直读 | 物理文件清单 | — | 私有索引，不建议手工搬移 |
| WMI `Win32_PnPSignedDriver` | 快速拿驱动列表 | 代码少 | 大机器上查询慢、字段偶有缺失 |

### 1.2 竞品参考

| 产品 | 思路 |
|---|---|
| Windows "重置/高级启动" | 依赖系统映像自带驱动，无用户侧备份概念 |
| Snappy Driver Installer | DriverStore 全量索引 + 本地驱动仓库包（数 GB），面向装机商 |
| Driver Booster / 360 驱动 | 云端版本库比对 → 下载厂商安装包 → 静默安装（更新向业务，非备份还原） |
| DoubleDriver / DriverBackup!（开源） | SetupDi 枚举 → 复制 .inf/.sys/.cat + 注册表导出（老式做法，Win10 后被 pnputil 全面取代） |

**结论**：IceClean 采用「**SetupDi 做展示层 + pnputil 做备份/还原执行层**」的组合，与微软自家支持路径一致，规避手工搬运 DriverStore 的兼容风险。云端更新比对不做自建库，P1 通过 Windows Update COM（IUpdateSearcher 过滤 Driver 类别）实现"官方源"检查。

## 二、功能设计

### 2.1 P0 —— 检测 / 备份 / 还原

**① 驱动检测列表（双视图）**

原 v1.0 计划以 `pnputil /enum-drivers` 作为唯一主列表（包视角）。经分析，当前 `DriverManager::GetDrivers()` 直接遍历 `SYSTEM\CurrentControlSet\Enum` + `Control\Class` 注册表的做法**正是本方案明确反对的手写注册表读取**，且存在以下缺陷，无法满足"显示已安装设备和驱动"的诉求：

- 只枚举带 `Driver` 子键的设备，漏掉大量 PnP 节点；
- 拿不到**设备状态/问题码**（禁用、驱动异常、未就绪），而这恰是设备视图最有价值的信息；
- 签名状态、安装状态无法可靠获取；
- 字段来源多处裸读，语言/格式变化即崩。

因此将"按设备视角"从**待确认项②提升为 P0 主视图**，并拆分为两个 Tab：

**Tab1 · 设备&驱动视图（SetupDi，默认在前，只读检测）**
- 数据源：`SetupDiGetClassDevsW(NULL, NULL, NULL, DIGCF_PRESENT | DIGCF_ALLCLASSES)` 枚举当前已呈现设备节点，配合 `SetupDiGetDeviceProperty` 取文档化属性、`CM_Get_DevNode_Status` 取状态/问题码。
- 字段：设备友好名（DEVPKEY_Device_FriendlyName/DeviceDesc）、厂商（Manufacturer）、设备类别（Class）、驱动描述（DriverDesc）、提供商（DriverProvider）、版本（DriverVersion）、日期（DriverDate）、INF 路径（DriverInfPath）、oemXX.inf（从 INF 路径提取）、**签名状态**（DEVPKEY_Device_DriverSignature）、**设备状态/问题码**（CM_PROB_* 翻译为 正常/禁用/驱动异常/未就绪）。
- 排序：设备类别分组 → 名称。顶部统计"N 个设备 · M 个含第三方驱动 · 异常 K 个"。

**Tab2 · 驱动包视图（pnputil /enum-drivers，备份/还原单元）**
- 数据源：解析 `pnputil /enum-drivers`（第三方包视角，双语键锚点兼容）。
- 字段：原始名/发布名称（oemXX.inf）、提供商、类别、版本、日期、是否签名（INF 属性推断）。
- 说明：备份/还原的操作单元是 DriverStore 包（oemXX.inf），与设备节点非一一对应，故独立成 Tab。
- 排序：类别分组 → 版本日期倒序；顶部统计"N 个第三方驱动 · 备份预计 X MB"（对 FileRepository 对应子目录求和抽样估算）。

**② 驱动备份**
- 入口：`[全量备份]`；单选行右键 `[备份此项]`
- 执行：`pnputil /export-driver * "<备份根>\<yyyyMMdd_HHmmss>\"`
- 备份根：`%DATA%\IceClean\Backups\Drivers\`（DATA=Roaming AppData，与其他数据一致）
- 进度反馈（ActivityTicker 模式）：后台线程每 500ms 扫描目标目录增量文件数 → "已导出 N 个文件 · 当前 xxx.cat"；结束显示总数与体积
- 元信息：目录内写 `manifest.json`（时间、系统版本、驱动条目数，复用 nlohmann/json + JsonUtil）

**③ 驱动还原**
- 入口：`[从备份还原…]` → 选择历史备份目录（列出含 manifest.json 的目录及元信息）
- 流程：确认对话框（危险级 Caution）→ **自动创建系统还原点** → `pnputil /add-driver "<dir>\*.inf" /subdirs /install` → 解析输出汇总（成功安装 / 已存在跳过 / 失败明细）
- 结果落 OperationLogger（type=Optimize, description 含备份目录与计数）

**④ 安全红线**
- 全程要求管理员（进程已是 requireAdministrator，仍显式校验）
- 还原前强制还原点；失败即中止且不删除任何既有驱动
- 不提供"卸载驱动"入口（P0 明确不做，误删风险高；列入 P2 评估）
- 关键服务/引导驱动不在任何删除路径中（我们只有导入，天然满足）

### 2.2 P1（可选，另行确认）—— 更新检查
- IUpdateSearcher（WUAPILib COM）`Search("IsInstalled=0 and Type='Driver'")` → 列出可更新驱动 → 引导用户走系统更新或厂商链接
- 不做第三方云版本库，避免供应链与合规负担

### 2.3 UI 改造点（现有 DriverPanel → wxNotebook 双 Tab）

**Tab1 设备&驱动（默认选中，SetupDi）**
```
[搜索____] [筛选: 全部/显卡/网络/...] [刷新]
┌─ 列表：设备名称 | 厂商 | 类别 | 驱动版本 | 日期 | 状态(正常/禁用/驱动异常) | 签名 ─┐
└─ 详情区：选中设备完整信息（含问题码说明）                                 ──┘
```
（此 Tab 为只读检测，无备份/还原入口；异常设备高亮提示）

**Tab2 驱动包（pnputil）**
```
[刷新] [全量备份] [从备份还原 ▾]                     [搜索____] [筛选: 全部/第三方/系统]
┌─ 实况条(ActivityTicker)：已导出 37 个文件 · netnvlm.inf ───────────────┐
├─ 列表：✔ | 名称 | 提供商 | 类别 | 版本 | 日期 | oem.inf ├
└─ 详情区：选中驱动完整信息 + [备份此项]
```
- 备份/还原按钮在操作期间禁用；完成后状态栏汇总 + 打开备份目录快捷链接

## 三、核心代码结构（拟新增）

> 注意：现有 `src/core/optimizer/DriverManager.*` 采用注册表遍历实现，按本方案原则应**迁移/重写为以下原生机制模块**，避免两套逻辑并存。原 `DriverManager` 降级为薄封装或直接废弃。

```
src/core/driver/
├── DeviceDriverInfo.h      // 数据模型（设备&驱动视图）：
│                           //   deviceName/manufacturer/deviceClass/driverDesc/
│                           //   provider/version/date/infPath/oemInf/
│                           //   signature/status/problemCode
├── DeviceDriverScanner.{h,cpp}  // SetupDi 设备&驱动枚举：
│                               //   SetupDiGetClassDevs(DIGCF_PRESENT|DIGCF_ALLCLASSES)
│                               //   + SetupDiGetDeviceProperty(DEVPKEY_*) 
│                               //   + CM_Get_DevNode_Status → 状态/问题码
├── PnpUtilRunner.{h,cpp}   // pnputil 封装：EnumDrivers()/ExportAll()/ExportOne()/AddDrivers()
│                           //   CreateProcess 隐藏窗口 + UTF-16 输出捕获 + 超时
├── DriverBackupManager.{h,cpp} // 备份编排：目录规划、进度轮询线程、manifest.json 读写
src/gui/panels/DriverPanel.cpp  // 改造为 wxNotebook 双 Tab 接入
```

## 四、CLI 验证方案（core_check_cli --drivers）

| 用例 | 断言 | 系统影响 |
| --- | --- | --- |
| SetupDi 设备&驱动枚举 | 条目 ≥1 且 deviceName/driverDesc 非空；异常设备识别字段可解析 | 只读 |
| EnumDrivers 解析（包视图） | 条目 ≥1 且字段非空（真实机必有第三方驱动如 Intel/NVIDIA） | 只读 |
| ExportAll 到 `%TEMP%\IceCleanCliDrv\` | 目录内 `*.inf` 数量 >0 且与 enum 计数一致 | 仅写 TEMP |
| manifest 写读往返 | version 字段一致 | TEMP |
| AddDrivers 还原 | **SKIP 默认**（真实安装改系统）；`--with-driver-install` 显式启用时对 TEMP 导出的 1 个最小包执行并校验返回码 | 显式 opt-in |

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| pnputil 输出格式随系统语言变化 | 按 UTF-16 输出逐段键值解析（"发布名称/Published Name"双语锚点），解析失败降级为原始行展示 |
| 导出大体积耗时（GPU 驱动可达 1-2GB） | 进度实况 + 备份前磁盘空间预检 + manifest 记录总量 |
| 用户还原到不匹配硬件 | 还原对话框明示用途；pnputil 对已存在同版自动跳过，重复导入无害 |
| 杀软拦截 pnputil 子进程 | 使用系统绝对路径 %WINDIR%\System32\pnputil.exe 调用 |

---

**已确认决策**：
- ②"按设备视角"**提升为 P0 主视图**（SetupDi），并作为默认在前的 Tab1；原 pnputil 包视图降为 Tab2。原 `DriverManager` 注册表遍历实现按本方案原则迁移/重写。
- ①备份根目录维持 `%DATA%\IceClean\Backups\Drivers\`（DATA=Roaming AppData）。
- ③P1 更新检查（IUpdateSearcher）暂缓，列为 D4 另议。

**仍待确认项**：①设备视图的筛选维度（按类别/厂商/异常状态）是否足够，是否需要按硬件树层级展示；②驱动包视图"备份预计 X MB"的估算精度要求。
