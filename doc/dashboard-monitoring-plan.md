# IceClean Dashboard 首页监控优化方案

> 制定日期：2026-09-03
> 说明：本方案提出将Dashboard改造为纯监控面板，移除所有扫描相关功能，突出硬件监控和健康度指标。

---

## 1. 现状问题分析

### 当前Dashboard问题
1. **功能定位模糊**：既要做仪表盘又要做扫描器，导致用户困惑
2. **快捷卡片误导**：6个快捷卡片（临时文件、更新缓存等）都触发全面扫描而非定向清理
3. **与DeepClean功能重复**：首页扫描 ≈ DeepClean 一键扫描
4. **资源浪费**：16个扫描器并行运行导致CPU/I/O饱和
5. **缺少硬件监控**：没有CPU/内存/磁盘/网络实时状态
6. **健康评分滞后**：仅在扫描后计算，无法实时反馈系统状态

### 与DeepClean功能重复（当前状态）

| 功能 | Dashboard 首页 | DeepClean 深度清理 |
|------|:-----------:|:---------------:|
| 一键扫描 | ✅ 16个扫描器并行 | ✅ 精细分类扫描 |
| 一键清理 | ✅ 清理选中项 | ✅ 分类清理 |
| 停止/取消 | ✅ | ✅ |
| C盘健康评分 | ✅ (扫描后) | ✅ (基于扫描结果) |
| 快捷入口卡片 | ✅ 6个卡片 | ❌ |
| 系统清理 | ❌ | ✅ 分类勾选 |
| 注册表清理 | ❌ | ✅ |
| 隐私清理 | ❌ | ✅ |
| 软件专清 | ❌ | ✅ |

**问题诊断**：
- 首页的6个快捷卡片全部只是触发"全面扫描"，点击行为与卡片语义不符
- 用户点击"临时文件"卡片，期望只扫描临时文件，实际扫描全部16个扫描器
- 首页既承担导航职责又承担扫描职责，定位不明确

### 业界优秀Dashboard设计参考

| 工具 | 首页设计 | 关键特点 |
|------|---------|----------|
| **WinUtil** | CPU/内存/磁盘实时监控仪表盘 | 实时资源使用率 + 快速入口 |
| **CCleaner** | 极简：仅Analyze按钮 + 分类列表 | 专注核心功能，无干扰项 |
| **O&O ShutUp10++** | 隐私仪表盘 | 安全等级色标 + 一键应用预设 |
| **BCUninstaller** | 软件列表为主 | 已安装应用清单 + 卸载操作 |

**业界共识**：
- 首页 = 仪表盘（Dashboard）= 状态展示 + 快速入口
- 清理 = 分类功能页 = 精细控制  
- 首页不承载扫描逻辑，只做导航和状态展示
- 监控指标应实时更新，而非仅在扫描后显示

## 2. 优化方案

### 方案：首页改造为纯硬件监控面板（推荐）

**核心思想**：Dashboard只做**硬件监控展示 + 系统导航入口**，不做任何扫描/清理逻辑。

#### 保留功能（监控类）
| 功能 | 说明 | 实现方式 |
|------|------|----------|
| **CPU监控** | 实时使用率/频率/核心数 | 环形图或数值显示 |
| **内存监控** | 实时使用率/已用/总容量 | 环形图或进度条 |
| **磁盘监控** | C盘使用率/已用/总容量/健康度 | 保留现有圆形进度条 |
| **网络监控** | 实时下载/上传速率 | 数值显示 |
| **系统健康评分** | 综合硬件状态评分 | 保留现有健康评分，改为实时计算 |
| **累计清理统计** | 历史清理总量 | 保留现有统计 |
| **导航入口** | 快速跳转功能页 | 保留6个卡片但改为纯导航 |

#### 删除功能（扫描/清理类）
| 功能 | 删除原因 |
|------|----------|
| 一键扫描按钮 | 首页不应承担扫描职责 |
| 一键清理按钮 | 首页不应承担清理职责 |
| 停止扫描按钮 | 扫描功能移除后无需停止 |
| 扫描进度条 | 扫描功能移除后无意义 |
| 扫描结果列表 | 扫描功能移除后无意义 |
| ScannerAggregator 全面扫描逻辑 | 与首页定位冲突 |
| 6个快捷卡片触发全面扫描 | 卡片语义与行为不符，改为纯导航 |

#### 首页快捷卡片改为纯导航

| 卡片 | 点击行为 | 跳转到 |
|------|----------|--------|
| 临时文件 | 跳转 | 深度清理 → 系统清理 Tab |
| 更新缓存 | 跳转 | 深度清理 → 系统清理 Tab |
| 浏览器缓存 | 跳转 | 深度清理 → 系统清理 Tab |
| 休眠文件 | 跳转 | 深度清理 → 系统清理 Tab |
| 启动加速 | 跳转 | 启动优化页 |
| 软件管理 | 跳转 | 软件管理页 |

### 业界最佳实践参考

| 功能 | WinUtil 实现 | CCleaner 实现 | O&O 实现 |
|------|--------------|---------------|----------|
| 资源监控 | CPU/内存/磁盘实时圆形图 | - | - |
| 磁盘使用率 | 环形图 + GB显示 | 分类清理前分析 | 系统驱动器状态 |
| 健康评分 | - | - | 隐私建议色标 |
| 导航入口 | 大图标 + 文字说明 | 功能分类列表 | 隐私开关分组 |
| 累计统计 | 历史清理总量 | - | - |
| 实时更新 | 1秒间隔 | 仅在用户触发时 | 实时建议 |

## 3. 详细设计

### 3.1 布局结构（建议）
```
┌─────────────────────────────────────────────────────────────┐
│                    IceClean 系统监控仪表盘                   │
├─────────────────────────────────────────────────────────────┤
│  CPU使用率  │  内存使用率  │  磁盘使用率  │  网络速率      │
│  [ ●●●○○○ 60%] [ ●●●●○○ 75%] [ ●●●○○○○ 40%] ↓1.2MB/s ↑800KB/s │
├─────────────────────────────────────────────────────────────┤
│  C盘健康状态                                                     │
│  [●●●●●○○○○○○] 65% 良好                                       │
│  本地磁盘 (C:)  45.2GB / 120.0GB                                 │
│  健康评分: 82 良好                                               │
│  累计清理: 128.5 GB                                              │
├─────────────────────────────────────────────────────────────┤
│  临时文件    更新缓存    浏览器缓存    休眠文件    启动加速    软件管理 │
│  [📁]       [🔄]        [🌐]        [⏸️]        [🚀]        [📦]      │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 监控指标实现方案

| 指标 | 数据源 | 更新频率 | 显示方式 |
|------|--------|----------|----------|
| CPU使用率 | PerformanceMonitor.GetCpuUsage() | 1000ms | 环形图 + 百分比 |
| 内存使用率 | PerformanceMonitor.GetMemoryUsage() | 1000ms | 环形图 + 百分比 |
| 磁盘使用率 | Win32Util.GetDiskSpace() | 5000ms | 保留现有圆形进度条 |
| 磁盘健康度 | HardwareDetector.GetDiskHealth() | 30000ms | 文字显示 |
| 网络下载速率 | PerformanceMonitor.GetNetworkDownloadSpeed() | 1000ms | 数值 + 单位 |
| 网络上传速率 | PerformanceMonitor.GetNetworkUploadSpeed() | 1000ms | 数值 + 单位 |
| 系统健康评分 | 综合CPU/内存/磁盘/网络加权计算 | 5000ms | 环形图或数值 + 色标 |
| 累计清理统计 | UsageStats.GetTotalCleaned() | 启动时 + 每次清理后 | 文字显示 |

### 3.3 健康评分计算方案
```cpp
// 权重：CPU 30% + 内存 30% + 磁盘 25% + 网络 15%
double healthScore = 
    (100 - cpuUsagePercent) * 0.3 +
    (100 - memoryUsagePercent) * 0.3 +
    (diskHealthPercent) * 0.25 +
    (100 - min(networkUtilizationPercent, 100)) * 0.15;

// 色标映射
if (healthScore >= 80) -> 绿色 (良好)
if (healthScore >= 60) -> 黄色 (一般)
if (healthScore < 60)  -> 红色 (较差)
```

### 3.4 导航行为优化
- 6个快捷卡片改为纯导航，不触发任何扫描
- 卡片采用透明背景+图标+文字的简洁设计
- 悬停时有淡色背景提示可点击
- 点击时有轻微按下反馈
- 导航延迟 < 100ms，保证即时响应

## 4. 实施步骤

### 阶段一：功能拆分与监控实现（P0）
1. **删除扫描相关UI**：移除一键扫描/清理按钮、进度条、停止按钮、扫描结果区域
2. **实现硬件监控模块**：
   - 集成PerformanceMonitor获取CPU/内存/网络实时数据
   - 保留并优化现有磁盘监控功能
   - 新增健康评分实时计算算法
3. **改造快捷卡片为纯导航**：修改点击事件仅执行页面跳转
4. **优化定时器**：将磁盘监控定时器改为5000ms，新增硬件监控定时器1000ms

### 阶段二：布局与视觉优化（P1）
1. **重新设计布局**：采用上述建议的四栏监控 + C盘状态 + 导航卡片结构
2. **统一视觉风格**：使用CardPanel包裹各监控模块，保持与现代风格一致
3. **添加动态反馈**：监控数值变化时有轻微动画（可选）
4. **优化文字层次**：标题/数值/单位使用不同字号和颜色

### 阶段三：性能与体验优化（P2）
1. **减少UI更新频率**：监控数据变化阈值触发更新（CPU变化>1%才更新UI）
2. **批量UI更新**：将多个监控更新合并为一次UI刷新
3. **内存优化**：监控历史数据仅保留最近N个点用于趋势显示（可选）
4. **异步数据获取**：确保监控数据获取不阻塞UI线程

### 阶段四：健康评分与报警（P3）
1. **实现健康评分综合算法**：根据CPU/内存/磁盘/网络计算综合分
2. **添加预警机制**：当任一指标超过阈值时在磁盘卡片上显示提示
3. **健康趋势图**：可选添加24小时健康评分趋势小图
4. **一键优化建议**：基于当前状态提供优化建议（跳转到相应功能页）

## 6. 风险评估与缓解措施

| 风险 | 可能影响 | 缓解措施 | 风险等级 |
|------|----------|----------|----------|
| 用户习惯改变 | 用户习惯点击卡片扫描 | 保持卡片图标不变，仅改变行为说明；添加工具提示说明“点击跳转” | 中 |
| 监控数据准确性 | 硬件数据获取失败 | 添加失败重试机制；数据异常时显示“数据不可用”而非错误 | 低 |
| 健康评分争议 | 评分算法不透明 | 在About页面提供评分计算方式说明；预留自定义权重接口 | 低 |
| 性能监控开销 | 定时器增加CPU占用 | 使用Windows高精度定时器；数据未变化时跳过UI更新；监控线程低优先级 | 低 |
| 功能发现性 | 用户找不到扫描入口 | 保持导航栏完整；在About页添加功能索引；首页卡片保持醒目位置 | 中 |

### 风险监控指标
- 首页加载时间 < 200ms (目标: 100ms)
- 监控数据更新成功率 > 99.9%
- 健康评分计算延迟 < 50ms
- UI帧率保持 > 55fps (目标: 60fps)
- 用户任务完成时间 (找到软件管理入口) < 3秒
