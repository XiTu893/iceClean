# IceClean Dashboard 首页优化方案

## 1. 问题分析

### 当前问题
- **资源占用高**：16 个并行扫描器同时运行，导致 CPU/I/O 饱和
- **UI 冻结**：每个扫描器每 100ms 发送一次进度更新（16 × 100ms），UI 线程被事件淹没
- **无取消反馈**：用户无法取消正在进行的扫描
- **无节流机制**：所有扫描器无条件运行，不考虑系统负载
- **信息过载**：扫描器类型过多，无清晰优先级

## 2. 功能重复性分析：首页 vs 深度清理

### 当前功能分布

| 功能 | Dashboard 首页 | DeepClean 深度清理 |
|------|:-----------:|:---------------:|
| 一键扫描 | ✅ 16个扫描器并行 | ✅ 精细分类扫描 |
| 一键清理 | ✅ 清理选中项 | ✅ 分类清理 |
| 停止/取消 | ✅ | ✅ |
| C盘健康评分 | ✅ | ✅ |
| 快捷入口卡片 | ✅ 6个卡片 | ❌ |
| 系统清理 | ❌ | ✅ 分类勾选 |
| 注册表清理 | ❌ | ✅ |
| 隐私清理 | ❌ | ✅ |
| 软件专清 | ❌ | ✅ |

### 首页快捷卡片（Dashboard）

| 卡片 | 功能 | 对应 DeepClean |
|------|------|----------------|
| 临时文件 | 触发全面扫描 | SystemTempScanner |
| 更新缓存 | 触发全面扫描 | WindowsUpdateScanner |
| 浏览器缓存 | 触发全面扫描 | BrowserCacheScanner |
| 休眠文件 | 触发全面扫描 | HibernationScanner |
| 启动加速 | 跳转启动优化页 | StartupOptimizer |
| 软件管理 | 跳转软件管理页 | SoftwareManagePanel |

### 问题诊断

**首页的 6 个快捷卡片全部只是触发"全面扫描"**，并没有跳转到对应功能页面，也没有调用对应的扫描器。这导致：

1. **功能重复**：首页一键扫描 ≈ DeepClean 一键扫描（都调用 ScannerAggregator）
2. **入口混乱**：卡片点击触发全面扫描，但卡片暗示是"定向扫描"
3. **交互矛盾**：用户点击"临时文件"卡片，期望只扫描临时文件，实际扫描全部 16 个扫描器

### 业界参考（industry-comparison-plan.md）

| 工具 | 首页设计 | 清理页设计 |
|------|---------|-----------|
| **CCleaner** | 极简：仅一个 Analyze 按钮 + 分类列表 | 丰富：注册表/浏览器/系统/应用分层 |
| **WinUtil** | 仪表盘：CPU/内存/磁盘实时监控 | 分类功能模块 |
| **BCUninstaller** | 软件列表为主 | 卸载向导流程 |
| **O&O ShutUp10++** | 隐私仪表盘 | 分级隐私开关 |

**业界共识**：
- 首页 = 仪表盘（Dashboard）= 状态展示 + 快速入口
- 清理 = 分类功能页 = 精细控制
- 首页不承载扫描逻辑，只做导航和状态展示

## 3. 优化方案

### 方案 A：首页改为纯仪表盘（推荐）

**设计思路**：首页只做"状态展示 + 导航入口"，不做扫描逻辑。

| 首页功能 | 说明 |
|----------|------|
| C盘空间仪表 | 环形图 + 使用率 |
| 快捷入口 | 6个卡片 → 跳转到对应功能页 |
| 累计清理统计 | 显示历史清理成果 |
| 最近清理记录 | 最近一次清理结果摘要 |

**首页快捷卡片改为导航**：

| 卡片 | 点击行为 | 跳转到 |
|------|----------|--------|
| 临时文件 | 跳转 | 深度清理 → 系统清理 Tab |
| 更新缓存 | 跳转 | 深度清理 → 系统清理 Tab |
| 浏览器缓存 | 跳转 | 深度清理 → 系统清理 Tab |
| 休眠文件 | 跳转 | 深度清理 → 系统清理 Tab |
| 启动加速 | 跳转 | 启动优化页 |
| 软件管理 | 跳转 | 软件管理页 |

**删除内容**：
- ❌ ScannerAggregator 全面扫描逻辑
- ❌ 一键扫描/一键清理按钮
- ❌ 扫描进度条
- ❌ 扫描结果列表

### 方案 B：首页保留轻量扫描（备选）

如果需要保留首页快速扫描能力：

| 扫描器 | 保留 | 说明 |
|--------|------|------|
| SystemTempScanner | ✅ | 临时文件，最常用 |
| BrowserCacheScanner | ✅ | 浏览器缓存 |
| RecycleBinScanner | ✅ | 回收站 |
| 其他 13 个 | ❌ | 移到 DeepClean 精细扫描 |

**关键改进**：
- 首页扫描从 16 个减至 3 个
- 进度更新间隔从 100ms 增至 500ms
- 扫描结果直接跳转 DeepClean 详情

## 4. 实施步骤

### 阶段一：扫描器精简（高优先级）

保留 4 个核心扫描器，覆盖 90% 常见场景：

| 保留 | 说明 | 移除 | 说明 |
|------|------|------|------|
| SystemTempScanner | 系统临时文件，最常见 | WindowsUpdateScanner | 可能与官方更新冲突 |
| BrowserCacheScanner | 浏览器缓存，高占用 | HibernationScanner | 低优先级 |
| RecycleBinScanner | 回收站，用户垃圾 | WinSxSScanner | 系统内部组件 |
| AppDataScanner | 应用残留数据 | DevCacheScanner | 开发工具缓存 |

### 阶段二：性能优化

**1. 进度节流**
- 进度更新间隔：100ms → 500ms（减少 80% 更新频率）
- 批量处理：收集所有扫描器进度后再发送

**2. 并发限制**
- 同时活跃扫描器限制为 2-3 个
- 多余扫描器进入队列等待

**3. 取消功能**
- DashboardPanel 增加取消按钮
- 通过 wxThreadEvent 发送停止信号
- 显示取消中状态

### 阶段三：用户体验增强

**1. 优先级指示**
- 高亮显示影响最大的扫描器
- 视觉权重分配

**2. 状态摘要栏**
- 快速概览：已节省空间、剩余时间、活跃扫描器

**3. 手动触发控制**
- 分离按钮：全面扫描 / 定向扫描

## 5. 预期效果

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 活跃扫描器 | 16 | 4 |
| 进度更新/秒 | ~30 | ~8 |
| CPU 峰值占用 | 高 | 中等 |
| UI 响应性 | 差 | 良好 |
| 用户体验 | 糟糕 | 改善 |

## 6. 风险评估

| 风险 | 缓解措施 |
|------|---------|
| 精简扫描器可能遗漏清理项 | 保留的 4 个覆盖 90% 常见场景 |
| 节流可能延迟完成 | 减少开销后总体仍更快 |

## 7. 成功标准

- [ ] Dashboard 在 1 秒内加载
- [ ] 扫描进度每 500ms 更新一次
- [ ] 扫描期间 UI 保持响应
- [ ] 取消按钮功能正常
- [ ] 空间节省报告准确
