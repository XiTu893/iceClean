# 深度清理「一键扫描 / 一键清理」交互提升方案

> 制定日期：2026-08-20
> 说明：针对「深度清理」模块现有交互（多标签页手动分步操作）进行简化，提出业界对标后的一键式交互方案。
> 本文仅为方案，确认后再实施。

---

## 一、现状与痛点

### 1.1 当前深度清理交互

深度清理面板共 4 个标签页，交互割裂：

| 标签页 | 扫描入口 | 清理入口 | 问题 |
|--------|---------|---------|------|
| 系统清理 | **无扫描**，4 个复选框 | 底部「开始系统清理」 | 清理前完全不知道会释放多少、影响多大，全靠用户盲点 |
| 注册表清理 | 「扫描注册表」 | 「清理选中项」 | 扫/清分两个按钮，需逐项勾选；清完自动重扫 |
| 隐私清理 | **无扫描** | 底部「开始隐私清理」 | 同上，无预览、无影响评估 |
| 软件专清 | 「扫描缓存」 | 「清理选中」 | 扫/清分离，但支持按软件展示大小，交互相对完整 |

- 每个标签页各自为政，**没有统一的"一键扫描"汇总**，也没有**统一的"一键清理"**。
- 系统清理 / 隐私清理无扫描预览；注册表 / 软件专清需手动逐项勾选后单点执行。
- 安全等级（Safe/Caution/Dangerous）仅在少数文案出现，未结构化驱动交互。
- 深度清理相关的 6 类任务要靠用户自行理解才敢操作，小白用户学习成本高。

### 1.2 核心痛点

1. **找不到、也不敢点**：没有全量扫描结果，用户不知道"能清什么、清多少、会不会出事"。
2. **步骤多**：扫一次、勾选、再点清理，跨 4 个 tab 来回切换。
3. **风险评估缺失**：危险项与安全项混在一起，用户无法快速获得"先清理安全的，危险项单独确认"的体验。

## 二、业界对表分析

### 2.1 主流产品交互模式

| 产品 | 一键扫描 | 一键清理 | 安全策略 | 可借鉴点 |
|------|---------|---------|---------|---------|
| **CCleaner**（业界标杆） | ✅ 健康检查整体扫描 | ✅ 一键式清理 | 扫描结果按项展示，需确认 | 一键式流程 + 分类结果清单 |
| **腾讯电脑管家** | ✅「一键扫描」 | ✅「立即清理」 | 扫描后**默认勾选"无风险"项**，深度清理项需**二次确认** | 安全项默认选中、危险项单独确认的"两级交互" |
| **360安全卫士** | ✅「一键清理」（内置扫描） | ✅「即扫即清二合一」 | 默认推荐项整合进一键清理；设置**误杀恢复区（封闭隔离）**，可恢复误删 | 扫清合并的"即扫即清"；**可恢复安全网** |
| **FluentCleaner**（开源新秀） | ✅ 单击扫描 | ✅ 一键清理 | 手动勾选确认后才执行；白名单过滤；命令行动态 | 可惜主动砍掉注册表清理（作者认为收益低风险高） |
| **BleachBit** | ✅ | ✅ | 勾选→预览→确认→删除 | 预览步骤明确 |
| **light-c**（开源新秀） | ✅ | ⚠️ 需逐级确认 | **风险等级标识 + 删除前显式提示**；作者明确建议"第一次先扫、先看列表、再勾选，别无脑一键清理" | 分级风险 + 显式确认，克制不过度自动化 |

### 2.2 业界共识（可提取的规律）

1. **"即扫即清"是简化交互的主流方向**：360（即扫即清二合一）、腾讯（扫描即展示、默认勾选安全项）、CCleaner（健康检查一键式）。但均保留了**危险操作二次确认**。
2. **安全项默认勾选 + 危险项单独确认**是标准做法（腾讯电脑管家明确定义"清理之后无任何风险的垃圾项默认选中"）。
3. **安全网是必备项**：清理前创建还原点 / 注册表导出备份（IceClean 已具备）、操作日志（已具备）、白名单保护（已具备）、可恢复隔离区（360 独有）。
4. **克制自动化**：light-c 作者等社区声音明确反对"无脑一键清理"，危险项（休眠文件、WinSxS、DISM）必须显式确认。FluentCleaner 甚至直接砍掉注册表清理。
5. **结果反馈**：清理后按分类展示释放空间、失败项，增强可信度（360 优化结果页分类展示）。

### 2.3 对 IceClean 的适配结论

- 适合做**"一键扫描 + 一键清理"**（提升可用性），但**必须保留危险项（🔴/🟡 高影响）逐个确认**（保持业界克制原则 + 项目"安全第一"铁律）。
- 现有基础设施已覆盖安全网：`RestorePointManager`（还原点）、`RegistryCleaner`（.reg 备份）、`OperationLogger`（日志）、`SafetyManager`/白名单、三级安全标识。

## 三、提升方案设计

### 3.1 目标交互模型（两段式 + 可选即扫即清）

```
                ┌────────────────────────────┐
 深度清理页 ──→ │     [ 🔍 一键扫描 ]          │   ← 顶部主按钮
                └────────────┬───────────────┘
                             ▼
                ┌────────────────────────────┐
                │   扫描结果汇总（按分类卡片）   │
                │  • 系统清理      8.4 GB      │
                │  • 注册表无效项   555 项      │
                │  • 隐私记录      123 项      │
                │  • 软件缓存     12 个/ 6.1GB │
                │   ┌──────────────────┐      │
                │   │ [ ⚡ 一键清理 ]    │      │
                │   └──────────────────┘      │
                └────────────┬───────────────┘
                             ▼
   清理流程（自动）：
   ① 创建系统还原点（全量清理前）
   ② 自动清理【安全级】项（无需逐项确认）
   ③ 逐一列出【危险级】项（🔴/🟡），用户逐个确认后才执行
   ④ 汇总结果：释放空间 / 成功项 / 失败项 分类反馈
```

设计原则：
- **安全项一键清，危险项逐个认** —— 与腾讯/360 一致，兼顾效率与安全。
- **保留专家入口**：4 个原标签页保留（"高级模式"），一键流程只是快捷入口，不做功能阉割。
- **默认不自动清危险项** —— 遵循 light-c/FluentCleaner 的克制原则与项目安全铁律。

### 3.2 「一键扫描」设计

在深度清理页顶部增加主按钮「一键扫描」，聚合执行：

| 扫描内容 | 数据来源（现有组件） | 输出 |
|----------|--------------------|------|
| 系统清理项 | 各专项 `Scanner`（Hibernation/WinSxS/oldWindows 容量探测） | 可释放容量估算、当前状态（是否启用/已清理） |
| 无效注册表项 | `RegistryCleaner::ScanInvalidItems()` | 数量 + 按类型分布 |
| 隐私记录 | `PrivacyCleaner` 各类型探测 | 数量 |
| 软件缓存 | `SoftwareCacheScanner` | 各软件缓存大小、数量 |

实现要点：
- 后台线程聚合扫描，进度条反馈；完成后汇总到统一结果视图。
- **风险分级驱动勾选默认态**：
  - `SafetyRating::Safe` → 自动勾选（可随时取消）
  - `SafetyRating::Caution`（如休眠文件、WinSxS、DISM）→ 默认**不勾选**，折叠在"高级项"分组，需展开确认
  - `SafetyRating::Dangerous` → 默认不勾选，需显式逐个确认
- 扫描结果缓存，避免重复扫描（即扫即清：第二次进入直接用上次结果 + 后台增量刷新）。

### 3.3 「一键清理」设计

点「一键清理」后自动编排清理队列：

1. **前置安全**：创建系统还原点（`RestorePointManager`）；注册表清理单独导出 `.reg` 备份（现有逻辑复用）。
2. **自动执行安全项**：文件垃圾、浏览器缓存、软件缓存、无效注册表项等 `Safe` 项，无弹窗直接清，进度条连续汇报。
3. **危险项逐一确认**：对 `Caution`/`Dangerous` 项弹出确认 (`ConfirmDialog`)，说明影响、影响量、是否可恢复；用户同意才执行。**默认建议仅清理安全项**。
4. **收尾**：`OperationLogger` 记录日志；结果页按分类展示：释放空间 / 成功项 / 失败项及失败原因；自动触发相关面板数据刷新（磁盘信息、扫描结果）。

### 3.4 「即扫即清」可选增强（P2，非必需）

- 设置项「启用即扫即清」：打开后点击主按钮直接 扫描→清安全项→列出危险项待确认，一键到底。
- 记住用户上一次的勾选偏好（记入配置），下次扫描自动套用（对齐 360 的省时设计）。

### 3.5 涉及现有代码结构（实施参考）

| 位置 | 改动 |
|------|------|
| `src/gui/panels/DeepCleanPanel.h/.cpp` | 顶部加主按钮区；新增"一键扫描/一键清理"处理函数；聚合结果视图；保留 4 个 tab 与现有 handler |
| `src/core/scanner/` | 新增 `DeepScanCoordinator.h`（可选）：编排各专项扫描 + 注册表 + 隐私 + 软件缓存，汇总为统一 `ScanCategory` |
| `src/core/cleaner/` | 新增 `DeepCleanCoordinator.h`（可选）：编排清理队列（还原点→安全项→危险项确认→日志→刷新） |
| `src/gui/MainWindow.cpp` | `StartDeepClean` / `OnCleanRequest` 事件扩展可复用（支持新的事件载荷）；清理完成回调扩展返回值结构 |
| 模型 | `ScanResult` / `ScanCategory` 扩展支持「分类汇总卡片」所需字段（预估容量、风险等级、默认勾选态） |

> 说明：如不做新 Coordinator 类，也可直接在 `DeepCleanPanel` 内聚合现有 `Scanner`/`Cleaner` 实例复用逻辑，改动更小，YAGNI 优先。

### 3.6 UI 结构变化（示意）

- 顶部：`[一键扫描] [一键清理]` 主操作按钮（一键清理在未扫描时禁用）。
- 扫描后：收起 4 个 tab 的分步操作入口为「高级模式/详细视图」链接，默认展示汇总卡片。
- 汇总卡片按分类展示：名称 / 数量 / 预估释放 / 风险等级徽标 / 勾选状态。
- 危险项折叠区：展开后列出逐项确认。

| 阶段 | 内容 | 主要工作 | 工作量 |

| **P2（可选增强）** | 即扫即清开关 + 记住上次勾选配置；扫描结果缓存与后台增量刷新 | 设置持久化；增量扫描 | 2 天 |

## 五、风险与对策

| 风险 | 对策 |
|------|------|
| 一键清理误删危险项 | 危险项（Caution/Dangerous）一律二次确认，默认不自动清；白名单 50+ 路径保护（已有） |
| 一键清理覆盖单个用户不想清的项 | 汇总视图保留逐项取消勾选；高级模式保留完整手控 |
| 扫描耗时长无反馈 | 后台线程 + 进度条 + 分类渐次出现 |
| 还原点创建失败 | 明确提示，允许用户选择"不创建继续"或"中止"（对齐现有处理） |
| 注册表误删 | 继续强制 .reg 备份（保留最近 5 份）+ 无效判定标准（PathExists 系统目录解析等）持续收敛误报 |
| 交互回退（用户喜欢旧的分步） | 保留 4 个 tab 高级模式，一键流程为新入口 |

## 六、待确认决策点

实施前请确认以下选择（否则按加粗默认值实施）：

1. **一键清理时，安全项是否直接自动执行？**（业界标准：是。是否要求"一键清理"前再弹一次整体确认框）
2. **`Caution` 级项**（休眠/WinSxS/DISM/删除旧系统等）：默认不勾选、展开后确认 —— 是否接受？
3. **是否要求"即扫即清"（P2）与"记住上次勾选"？** 还是本期只做 P0+P1？
4. **一键扫描结果是否需要"预估可释放容量"**（需对系统项做容量探测，扫描时间略增）；还是仅显示数量？
5. **原始 4-tab 分步操作**是否保留为「高级模式」入口（建议保留，零风险）？
